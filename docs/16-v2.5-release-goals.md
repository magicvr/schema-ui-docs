# v2.5 发布目标与 accept 门禁

本文档是 **v2.4 → v2.5** MINOR 的 **accept + 原子落地** 门禁清单。在本文件 G0–G5 与发布工程门禁全部勾选前：

- 不得将 ADR-0025 / 0026 / 0027 标为 `accepted` 却不同步下游投影；
- 不得把三 ADR 写入 `protocol-manifest.json` 的 `authority.semanticSpecs`；
- 不得发布 `protocolVersion: "2.5"` 协议制品。

**设计可接受性**已由归档审计 [0069](./audit/archived/0069-2026-07-27-review.md)（V313–V330）在提案层闭合；本文件不再重开设计刀口，只跟踪 **accept 决议与机器/文档投影**。

| 轨道 | ADR | capability | 说明 |
|---|---|---|---|
| 应用级（新） | [0025](./decisions/0025-app-manifest.md) | `app.manifest` | 清单、注册表、home、D4a、基址三分法 |
| 应用级（可选） | [0026](./decisions/0026-app-navigation.md) | `app.navigation` | 依赖 0025；导航槽位/过滤/高亮 |
| 页面级 | [0027](./decisions/0027-table-sort-declaration.md) | `table.sort` | 依赖 0011 wire；与应用级零耦合 |

迁移（落地时新建）：`docs/migrations/2.4-to-2.5.md`。  
应用级规范正文（落地时新建）：`docs/17-app-manifest.md`  
（ADR-0025 草案曾写 `16-app-manifest`；与本门禁文件 `16-v2.5-release-goals` 错开编号，accept 时以本门禁与 `17` 为准，并回写 ADR 交付路径。）

## 1. v2.4 到 v2.5 的边界

### 1.1 版本与 dual-track

| 制品 | 版本字段 | 协商对象 |
|---|---|---|
| 页面 schema | `meta.protocolVersion: "2.5"` | 沿 ADR-0009；仅当页使用 2.5 字段集时要求 |
| 应用清单 | 顶层 `protocolVersion: "2.5"` | 只协商应用级能力；**不**迫使注册页升级（0025 D1a） |
| 协议制品 | 建议 `artifactVersion: 2.5.0` / `protocolVersion: "2.5"` | 与根包、lockfile、MCP 捆绑声明对齐 |

- Renderer `supportedVersions` 可同时包含 `"2.4"` 与 `"2.5"`（及更早已支持 MINOR）。
- **清单 2.5 + 页 2.1/2.4/2.5 混部合法**；页协商失败只拒该页。
- 未提供清单的后端：页面级对接与 v2.4 完全一致（应用级可选）。

### 1.2 新增 capability 与字段集

| capability | 出现即要求 | 主要字段 / 端点 |
|---|---|---|
| `app.manifest` | 清单 `requiredCapabilities`；字段集下限清单 `"2.5"` | well-known 或显式 manifest URL；`app` / `pages[]` |
| `app.navigation` | 清单出现 `navigation` 键 | `navigation.top` / `sidebar` / `user` |
| `table.sort` | 页使用 `sortable` / `sortField` / `defaultSort` | ColumnDef + `table.props.defaultSort`；页 `"2.5"` |

### 1.3 additive / 回归底线（不得破坏）

- 合法 **v2.4 页面**（无 `table.sort` 字段）：无协议级排序 UI 义务；不得猜列可排（0027 / 0011）。
- 未声明 `app.manifest` 的 Renderer：不实现清单；既有单页流程不变。
- 仅 `app.manifest`、无 `app.navigation`：不得部分解析 `navigation`（生产方 M1：有键必声明 capability）。
- `navigate` **不强制**命中注册表；**命中则必须**按 D4a 注入 `$context.route`（0069/V314）。
- 0011 的 `sort` wire、四层合并、D4 状态表 **零修改**；0027 只补声明面与点击语义。

### 1.4 明确不进 v2.5（非目标，门禁不验收）

- 登录 / OAuth / token 协议、权限中台  
- 面包屑、菜单 badge、第二侧边栏、logout 动作类型  
- 多列排序、client/none 本地排序、route 可选段/通配/尾斜杠归一  
- `navigate` 强制命中注册表；`MANIFEST_ROUTE_AMBIGUOUS` 稳定码  
- 主题 / CSS / 左/右侧栏呈现

### G2. 结构与静态校验

- [ ] 校验层级命名写入 `17-app-manifest.md`（M0/M1/M3a；有意无 M2）。

### G3. 可观测算法与 conformance（0069 意图 → fixtures）

> 下列每条须有 versioned fixture（或扩展既有 suite），JS/Python reference 同结果。

#### G3a. suite `app-manifest`（或等价）

- [ ] 清单版本精确协商正负例（`UNSUPPORTED_PROTOCOL_VERSION` / `MISSING_PROTOCOL_VERSION`）。
- [ ] 清单/页面版本解耦。
- [ ] 缺 `app.manifest`；有 `navigation` 无 `app.navigation` → M1/拒绝。
- [ ] `homePageRef`：未知 id；含参 route 拒绝；深链接优先；落地 path = route 字面量。
- [ ] **D4a 消歧**：`/orders/new` vs `/orders/{id}` → 字面量胜；声明序并列；尾 `/` 不归一。
- [ ] **D4a 解码**：percent-decode 段；`+` 字面；非法 `%` → 候选失败。
- [ ] `schemaUrl`：API `baseURL` 拼接；占位绑定；未解析 → `MISSING_PATH_BINDING`。
- [ ] `pageId` ≠ schema `meta.pageId` → `MANIFEST_PAGE_ID_MISMATCH`。
- [ ] logo：相对 path 拼接；`https:` 原样；`http:`/`data:` 拒绝。
- [ ] manifest 加载失败 → `MANIFEST_LOAD_FAILED`，不渲染页。
- [ ] **navigate 命中注册表必须注入** `$context.route.params`；未命中不拒绝 navigate。
- [ ] 空 `pages` + 仅 `url` 导航壳合法；`pageRef` 非法。

#### G3b. suite `app-navigation`

- [ ] 三槽位；未知槽位结构失败。
- [ ] `pageRef`/`url` 互斥；组不嵌组；`pageRef` 引用完整性。
- [ ] 过滤：缺省未声明 → 可见；`permissions.view` AND `visibleWhen`；空组剪枝。
- [ ] 数组序稳定；icon 无映射 → 省略图标仍渲染文本。
- [ ] 高亮：`pageRef` 单项 D4a；`url` 全等；query 不参与；多 active 允许。

#### G3c. suite `table-sort` 或扩展 `search-table`

- [ ] 无 `table.sort` / 无 `sortable`：不产生协议排序交互（v2.4 兼容）。
- [ ] 有字段无 capability 或 version &lt; 2.5 → L2 拒绝。
- [ ] 三态：无序→`asc`→`desc`→清；`page` 重置 1；搜索保留 sort。
- [ ] `defaultSort` 初始请求；**desc 初始时首次点该列 → 清除**。
- [ ] `sortField` 映射；不可排序列不产生 sort；sortKey 冲突 L2。
- [ ] 未知 sortKey → `TABLE_SORT_FIELD_UNKNOWN`，**不发请求**。
- [ ] 与 `table.selection`：sort 变化清空选中（沿 0022）。
- [ ] 既有 0011 search-table wire 向量保持通过（回归）。

## 5. 版本纪律

- v2.5 为 **MINOR**：合法 2.4 输入与默认可观测结果不得被静默改变。
- 文档勘误 → PATCH；再增兼容字段/capability → 新 MINOR；收紧合法输入或改默认行为 → MAJOR。
- 应用级与页面级 capability **独立 opt-in**；不得要求「用了清单就必须全站页升 2.5」。
