# 从 v2.7 迁移到 v2.8

本文是 **informative** 升级路径，不改变 v2.7 制品语义。v2.8 是 additive MINOR：只新增可选
document/字段/capability，旧页面、旧 manifest、既有 401/403 与 Action 可观测结果不变。

## 1. 总览

| 变更 | 类型 | 是否需要动作 |
|---|---|---|
| 新增可选 `host.bootstrap` capability 与 bootstrap document | 可选新增 | 否（未声明该 capability 的 Host 不请求、不受约束） |
| 新增可选 `host.failure-recovery` capability 与 Host failure result | 可选新增 | 否（不产生 failure result） |
| 新增可选 `host.conformance-claim` capability 与 claim 制品 | 可选新增 | 否（不产生 claim） |
| app manifest `pages[].returnIntentQueryKeys` 字段 | 可选新增 | 仅声明该字段的 App（须 2.8 + capability） |
| capability ID 机读语法段内允许连字符 | additive 增宽 | 否（此前合法 ID 全部不变） |
| 算法类 fixtures 与官方场景统一 `protocolVersion: "2.8"` | 版本线推进 | 消费者按版本过滤的互操作向量随之更新 |

## 2. 不做什么（零动作项）

- 不改变 ADR-0025 一次性 manifest snapshot、默认入口或合法输入；
- 不改变 `legacy adapter` 边界：无 `protocolVersion` 的旧文档仍必须在入口前显式选择 adapter；
- 不改变既有 401 → `onAuthFailure`、403 → forbidden、`400 + errors` 字段回填、Action `onError`
  顺序与允许行为；
- 不改变未知字段 fail-closed（manifest 顶层仍无 `extensions` 逃逸口）；
- 不改变 `requestMapping`、`actions.upload`、query 保留名（`page` / `pageSize` / `sort`）等既有规则；
- 不新增对 `form.controls.advanced` / `extended` 等既有 capability 的要求。

## 3. 可选升级：声明新 capability 的 Host

只有「选择声明新 capability」的 Host 才需要执行以下动作，且必须先通过对应 capability 的全部
机器契约与 evidence 门禁（见 [10-host-interoperability.md](../10-host-interoperability.md) §5）：

1. **`host.bootstrap`**：实现 bootstrap document 发现（`GET
   {baseURL}/.well-known/schema-ui/host-bootstrap.json`，`credentials: omit`，仅 `404`/`410`
   回退 ADR-0025 入口，其余 fail-closed）与确定性启动生命周期（validation → availability →
   auth → manifest-load → integrity → manifest-validation → context → ready）；
2. **`host.failure-recovery`**：实现归一化 failure result（§3）、分类优先级（§2.7）、
   retry 语义（§3.5）、return intent allowlist（§3.7）与 A11y 最低义务（§3.8）；既有节点/Action
   错误处理不变；
3. **`host.conformance-claim`**：生成绑定 protocol artifact digest、fixture digest 与 build ID 的
   静态 claim，并消费同一规范化/digest 实现（§4.3）。

## 4. 可选升级：声明新字段的 App

- 仅在清单声明 `pages[].returnIntentQueryKeys` 时，清单必须满足
  `protocolVersion >= "2.8"` 且 `requiredCapabilities` 含 `host.failure-recovery`
  （否则 M1 `PROTOCOL_VERSION_TOO_LOW` / `MISSING_REQUIRED_CAPABILITY`）；
- 敏感 key（大小写不敏感的 `token` / `access_token` / `id_token` / `code` / `state` /
  `session` / `redirect` / `returnTo`）即使误被声明，Host 消费端也永久拒绝。

## 5. 双轨与兼容矩阵

| 输入 | v2.7 Host | v2.8 Host |
|---|---|---|
| v2.7 页面 / manifest | 原行为 | 原行为（协商接受 2.7） |
| v2.8 页面（无 host capability） | 按版本协商拒绝或接受（若 Host 支持 2.8） | 按版本/capability 协商 |
| 声明 `host.*` capability 的 App/Host | 不支持（`MISSING_REQUIRED_CAPABILITY`） | 按 [10](../10-host-interoperability.md) 门控消费 |

## 6. 升级动作汇总

- 纯 additive、capability 门控、**无强制迁移动作**；升级动作只存在于「选择声明新 capability
  的 Host」一侧（ADR-0034 D9）。
