# 从 v2.8 迁移到 v2.9

本文是 **informative** 升级路径，不改变 v2.8 制品语义。v2.9 是 additive MINOR：只新增可选
capability 与值语法扩展，旧页面、旧 manifest、既有请求构造与 Action 可观测结果不变。

## 1. 总览

| 变更 | 类型 | 是否需要动作 |
|---|---|---|
| `data.params` / `optionsSource.params` / `datasources.*.params` 值语法新增 `$context.route.query.*` / `$context.route.params.*` 整值绑定（ADR-0039） | 可选新增 | 仅使用该绑定的页面（须 `2.9` + `data.route-binding`） |
| 表单字段 `props.readOnly` 声明（ADR-0040） | 可选新增 | 仅声明该 props 的页面（须 `2.9` + `form.controls.readonly`） |
| capability-registry 新增 `data.route-binding` / `form.controls.readonly` | 可选新增 | 否（未声明即不参与协商） |
| 算法类 fixtures 与官方场景统一 `protocolVersion: "2.9"` | 版本线推进 | 消费者按版本过滤的互操作向量随之更新 |

## 2. 不做什么（零动作项）

- 不改变 `$deps.*` 的既有规则（仅表单上下文、完整单个整值替换、tombstone 删除）；
- 不改变字面量 params、`$context.route` 在 recordSource path/query 的既有绑定；
- 不改变 `$context.route` 在表达式挂载点（reactions / visibleWhen / permissions）的禁令；
- 不改变 DataRef url `?` 禁令、query 保留名（`page` / `pageSize` / `sort`）、ADR-0010
  序列化与 ADR-0011 合并顺序；`requestMapping` / `navigateMapping` / `bodyMapping` /
  `actions.upload` 的既有规则全部不变；
- 不改变 legacy adapter 边界：无 `protocolVersion` 的旧 v0.1 文档仍必须在入口前显式选择
  adapter，且 adapter 输出须重新通过目标版本 L0–L4 与标准协商（`08` §3.3）；
- 不新增 `type: hidden` 或静态 `disabled` prop（ADR-0040 D5 明确非目标）。

## 3. 可选升级：使用 params 路由绑定的页面

若 `data.params` / `select.props.optionsSource.params` / 页面级 `datasources.*.params`
的参数值使用 `$context.route.query.<name>` 或 `$context.route.params.<name>` 完整单个
整值绑定：

1. `meta.protocolVersion` 必须为 `"2.9"`（或更高 MINOR）；
2. `meta.requiredCapabilities` 必须包含 `data.route-binding`；
3. 绑定值缺失时该参数按 tombstone 从最终 query 删除（与 `$deps` 空值一致）；
   需要 fail-closed 的场景由业务 API 契约或页面逻辑承担；
4. 绑定键只允许单段标识符（`$context.route.query.dictKey` 合法；
   `$context.route.query.a.b`、`$context.route.path` 非法）。

示例：

```yaml
meta:
  protocolVersion: "2.9"
  requiredCapabilities:
    - data.route-binding
body:
  type: table
  id: dict-entries-table
  props:
    rowKey: id
    pagination: { mode: server, pageSize: 20 }
    columns:
      - { field: entryKey, label: 条目键 }
  data:
    source: api
    url: /api/data-dictionary/entries
    params:
      dictKey: $context.route.query.dictKey
```

## 4. 可选升级：使用 `readOnly` 的表单

若任一表单字段控件（input / inputNumber / textarea / switch / checkbox / radio / select /
datePicker / dateRangePicker / upload / cascader / checkboxGroup / richText / password）
声明 `props.readOnly: true`：

1. `meta.protocolVersion` 必须为 `"2.9"`（或更高 MINOR）；
2. `meta.requiredCapabilities` 必须包含 `form.controls.readonly`；
3. 只读字段用户不可编辑，但值仍参与 `values` 与提交投影（`bodyMapping`）；
   `defaultValue` / `recordSource` 回填 / reactions 写入照常生效；
4. `required` 校验照常应用（页面生产方须保证值源）。

示例：

```yaml
meta:
  protocolVersion: "2.9"
  requiredCapabilities:
    - form.controls.readonly
    - form.record.load
actions:
  updateEntry:
    type: request
    method: PATCH
    url: /api/data-dictionary/entries/{id}
    bodyMapping:
      dictKey: dictKey
      label: label
body:
  type: form
  props:
    submitAction: updateEntry
    recordSource:
      method: GET
      url: /api/data-dictionary/entries/{id}
      responseMapping:
        dictKey: dictKey
        label: label
  children:
    - type: input
      props: { field: dictKey, label: 类型键, readOnly: true }
    - type: input
      props: { field: label, label: 标签 }
```

## 5. 双轨与兼容矩阵

| 输入 | v2.8 Renderer | v2.9 Renderer |
|---|---|---|
| v2.8 页面（无新 capability） | 原行为 | 原行为（协商接受 2.8） |
| v2.9 页面（无新 capability） | 按版本协商拒绝或接受（若 Renderer 支持 2.9） | 按版本协商 |
| 声明 `data.route-binding` / `form.controls.readonly` 的页面 | 不支持（`MISSING_REQUIRED_CAPABILITY`） | 按 capability 协商消费 |

## 6. 升级动作汇总

- 纯 additive、capability 门控、**无强制迁移动作**；升级动作只存在于「选择使用新 capability
  的页面生产方」一侧（ADR-0039 D4 / ADR-0040 D4）。
