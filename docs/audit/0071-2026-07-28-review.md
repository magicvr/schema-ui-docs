## 问题详情

### V336 — 应用清单缺少 v2.5 字段集下限（P1）

**位置：** `conformance/reference-js/app-manifest.js`、`conformance/reference-python/app_manifest.py`、`docs/17-app-manifest.md`、`docs/release-goals/v2.5.md`。

**当前行为：** M1 仅验证 `protocolVersion` 是 MAJOR.MINOR 形态，并检查 capability；`protocolVersion: "2.4"` 加 `app.manifest` capability 的完整清单会在 JS 与 Python reference 中返回 `ok: true`。

**冲突与影响：** v2.5 门禁和清单正文均将应用清单定义为 v2.5 字段集。旧 Renderer 可被误导为消费新清单，破坏严格版本协商与 fail-closed 边界。

**建议修复：** 在 M1 与双语言 reference 统一拒绝 `< "2.5"` 的应用清单；新增 JS/Python 共用反例 fixture，并写明错误码和路径。

**验证：** 新反例被 `test:conformance:app-manifest` 和 Python 入口拒绝；既有清单 2.5 与清单 2.5 + 页面 2.4 解耦正例继续通过。

### V337 — 导航 M3a 静态表达式校验未落地（P1）

**位置：** `docs/17-app-manifest.md`、`conformance/reference-js/app-navigation.js`、`conformance/reference-python/app_navigation.py`。

**当前行为：** `visibleWhen: { when: "$deps.admin == true" }` 的 navigation 在 JS/Python `validate` 中都通过，运行时被静默隐藏。

**冲突与影响：** M3a 要求导航表达式复用非表单 L3a 规则，仅允许 `$context.user.*` / `$context.features.*`，非法表达式须报告。当前结果将生产配置错误伪装成权限过滤结果。

**建议修复：** 实现并复用清单作用域 M3a 检查；将结果作为 `validate` 的结构化错误，并补 `$deps`、`$row`、`$self`、非法语法与合法 `$context` fixture。

**验证：** JS/Python navigation conformance 对非法表达式返回相同 M3a 错误；合法过滤、空组剪枝与高亮向量不回归。

### V338 — API `baseURL` 与应用路由根语义冲突（P1）

**位置：** `docs/17-app-manifest.md`、`docs/07-actions-contract.md`、`docs/decisions/0021-record-navigation-and-form-load.md`、`docs/schemas/action.schema.json`、`docs/schemas/app-manifest.schema.json`。

**当前行为：** `17` 定义 request/schemaUrl 走 API `baseURL`、navigate 走应用路由根；`07` 将 request URL 写为应用路由根，action Schema 又将 navigate URL 写为 `baseURL` 下路径。

**影响：** API 为 `https://api.example.test/v1`、应用根为 `https://app.example.test` 时，`/orders/1` 的请求或导航目标随实现选择不同 host。

**建议修复：** 以 `17` D1b 为唯一语义来源，同步 `07`、ADR-0021 与两个 Schema 描述；为 Action request、recordSource、navigate 与 OutcomeBehavior navigate 增加 baseURL/route-root 对照测试。

**验证：** 规范、Schema 描述、request construction fixtures 和 MCP 校验输出对同一基址矩阵一致。

### V339 — 页面 Schema 版本说明与 capability 列表滞后（P2）

**位置：** `docs/schemas/page.schema.json`。

**当前行为：** `meta.protocolVersion` 描述仍称当前制品为 `"2.4"`，`requiredCapabilities` 描述遗漏 `app.manifest`、`app.navigation` 和 `table.sort`；`01` 正文已为 2.5。

**建议修复与验证：** 同步描述到 2.5 全量 capability；执行 JSON parse、`check:links`、MCP build/test，并确认协议制品的 Schema 描述一致。

### V340 — MCP 文档索引遗漏 v2.5 权威正文（P2）

**位置：** `mcp/src/core/protocol-index.ts`、`mcp/tests/search.test.ts`。

**当前行为：** `DOC_MAP` 没有 `docs/17-app-manifest.md`，`v2-release-goals` 仍指向 `v2.0.md`。`protocol.get_doc` 无法通过稳定 docId 读取应用清单，search 也不纳入该正文。

**建议修复与验证：** 增加 `app-manifest` docId、令稳定 v2 release-goals 指向当前 v2.5 门禁（或改成显式版本化 id）；补 get_doc/search tests、tools smoke 和 MCP Docker smoke。

### V341 — MCP 可由环境变量改用外部协议或验证器根目录（P2）

**位置：** `mcp/src/core/paths.ts`、`mcp/src/core/validation-runner.ts`、ADR-0007 D9。

**当前行为：** `SCHEMA_UI_PROTOCOL_ROOT` 和 `SCHEMA_UI_VALIDATOR_ROOT` 优先于镜像内置根目录；运行配置可使服务读取外部协议文件或加载外部 validator 脚本。

**影响：** 需要部署者或宿主进程注入环境变量，不是普通 MCP 调用方可触发；但与“只读内置制品、不读取宿主项目文件”的公开边界冲突。

**建议修复与验证：** 生产 Docker 入口忽略这两个变量，或将覆盖能力限制为显式 development-only 开关并写入文档；增加容器环境变量注入回归，断言仍使用镜像内置 digest 和 validator。

### V342 — 场景 frontmatter 版本漂移未被 runner 覆盖（P2）

**位置：** `docs/05-scenarios/permission-inheritance.md`、`scripts/official-scenarios.js`、两个 scenario execution reference。

**当前行为：** 文档 frontmatter 仍为 `v2.4`，YAML page meta 已为 `"2.5"`；runner 只读取 YAML fence，所以此漂移不会被场景验证发现。

**建议修复与验证：** 同步该 frontmatter；提取并比较白名单场景的 frontmatter `applies_to` 与 YAML `meta.protocolVersion`，或明确 frontmatter 非机器输入并加入独立一致性检查。

### V343 — Docker build context 未隔离且 CI 未观察隔离规则（P3）

**位置：** 仓库根缺 `.dockerignore`、`mcp/Dockerfile`、`.github/workflows/mcp-ci.yml`。

**当前行为：** Docker 使用根目录作为 build context；被 `.gitignore` 忽略的 `.env` 等本地文件仍会发送给 builder。Dockerfile 未将它们复制进最终镜像，但上下文边界没有防护，且未来 `.dockerignore` 变化不会触发 MCP CI。

**建议修复与验证：** 新增最小白名单式 `.dockerignore`，并将其纳入 MCP CI paths；使用临时哨兵文件构建，确认其不在 build context，重跑 Docker smoke。
