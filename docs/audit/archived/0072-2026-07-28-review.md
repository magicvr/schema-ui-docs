### V345（🟡 P2）MCP 文档仍写「需等 `mcp-v2.5.1` 发布」— 已关闭

**位置：** [`docs/mcp/README.md`](../../mcp/README.md)（「当前版本示例」段）。

**当前行为：** 文案称工作树 MCP 为 `2.5.1`，并写「正式拉取需等 `mcp-v2.5.1` 发布」。

**冲突证据：**

- 本地 tag 存在 `mcp-v2.5.1`；MCP CD run 成功。
- `docker pull ghcr.io/magicvr/schema-ui-mcp:2.5.1` 成功；digest `sha256:bc16dc34…`。
- 正式镜像 `smoke:docker` 通过（含 `appManifestDocOk`）。
- 同文件下方 pull/run 示例已使用 `2.5.1`，与「需等发布」自相矛盾。

**影响：** 读者/客户端可能误判正式 GHCR 尚未可用，重复 0070/V334 类入口卫生问题。

**建议修复与验证：**

1. 改为已发布口径（例如「正式 tag `mcp-v2.5.1`；pin 完整版本」），删除「需等发布」。
2. 全文检索 `需等` / `mcp-v2.5` 残留。
3. 验证：人工对照 `mcp/package.json` 与已发布 tag；**不**改协议 contentDigest（`docs/mcp/**` 不进制品）。

**所属类型：** 发布完整性 / 文档入口。

### V346（🟡 P2）`release-check` 未对权威 `17` 做 `applies_to` 门禁 — 已关闭

**位置：** [`scripts/release-check.js`](../../../scripts/release-check.js) 中 `coreSpecPaths`；对照根 [`protocol-manifest.json`](../../../protocol-manifest.json) `authority.semanticSpecs`。

**当前行为：** V231 门禁要求 `docs/01`–`08` 含 `applies_to: schema-ui-protocol v${protocolVersion}`；**不包含** `docs/17-app-manifest.md`。`docs/00-overview.md` 另有版本字符串检查，但亦不在 `coreSpecPaths` 的 `applies_to` 循环内。

**冲突证据：**

- `protocol-manifest.json` 将 `docs/17-app-manifest.md` 列为 semanticSpecs（应用级权威正文）。
- 当前 `17` frontmatter 已为 `applies_to: schema-ui-protocol v2.5`（**现无漂移**）。
- 下一 MINOR 若只升 `01`–`08` 的 `applies_to` 而漏改 `17`，`release:check` 仍可通过。

**影响：** 权威层版本锚点观察不完整；属**预防性门禁缺口**，非当前 2.5 语义错误。

**建议修复与验证：**

1. 将 `docs/17-app-manifest.md` 纳入 `coreSpecPaths`（或等价的 authority 文档列表）。
2. 可选：将 `docs/00-overview.md` 的 `applies_to` 也纳入同一循环（与现有 overview 版本字符串检查互补）。
3. 验证：`npm run release:check`；临时改坏 `17` 的 `applies_to` 应 fail-closed，再恢复。

**所属类型：** 门禁 / 契约投影卫生。

### V347（⚪ P3）Protocol CI 未观察 L0–L4 等校验脚本路径 — 已关闭

**位置：** [`.github/workflows/protocol-ci.yml`](../../../.github/workflows/protocol-ci.yml) `on.pull_request.paths` / `push.paths`。

**当前行为：** Protocol CI 仅显式观察：

- `scripts/build-protocol-artifact.js`
- `scripts/verify-protocol-artifact.js`
- `scripts/release-check.js`
- `scripts/check-links.js`
- `scripts/run-all-conformance.js`

**冲突证据：**

- 本地门禁与 Protocol job 会执行 `validate:scenarios`（依赖 `scripts/validate-scenarios.js` 与 L2/L3a/L4 脚本），但这些脚本**单独变更不触发** Protocol CI。
- [`validator-ci.yml`](../../../.github/workflows/validator-ci.yml) / [`mcp-ci.yml`](../../../.github/workflows/mcp-ci.yml) 使用 `scripts/**`，可部分兜底（场景校验、MCP 测试），但**不会**跑 `test:conformance:all`。
- 与 V343「CI 未观察隔离规则」同类：观察面小于实际执行面。

**影响：** 仅改辅助校验脚本时，全量 dual-language conformance 可能不在 PR 上重跑。算法 suite 本身不依赖 L2 时风险较低；仍属维护性缺口。

**建议修复与验证：**

1. 将 Protocol CI 的 scripts 观察面扩为 `scripts/**`，或至少补上 `validate-*.js` / `lint-l4-*.js` 及场景提取相关脚本。
2. 验证：对上述路径的空提交或 workflow 语法检查；确认 PR 会触发 Protocol CI。

**所属类型：** 门禁卫生。
