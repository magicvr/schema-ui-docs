# 审计报告 0069：ADR-0025 / 0026 / 0027 交叉可接受性评审

## 结论

**提案层可接受性缺口已按推荐裁决闭合；三 ADR 仍为 `proposed`，不得直接标 `accepted`。**

## 已对齐、应保留的设计

1. **轨道切分**：应用级（0025/0026）与页面 table 声明面（0027）零依赖；`11` 不收应用级是预期。
2. **additive / fail-closed**：`sortable` 缺省 `false`；未声明 `table.sort` 不得猜列可排；清单/导航双 capability；未知顶层字段与未知槽位拒绝。
3. **鉴权分层未削弱**：注册表/菜单是发现与呈现面；页面 `permissions` + 后端鉴权独立；token/登录保持章程非目标。
4. **0027↔0011 接缝克制**：不改 `sort` wire、四层合并、D4 事件表；与 0022 选中清空沿用既有口径。
5. **M 系列与 L0–L4 平行**：清单制品不混用页面管线。
6. **清单版本与页面版本解耦（0025 D1a）**：装载 2.5 清单不要求全站页升级。
7. **MVP 非目标**：面包屑、badge、第二侧边栏、logout 动作类型、多列排序、client 本地排序——排除合理。

### V313（🔴）D4a 消歧：字符长度最长优先与示例意图相反 — 开放（阻断 accepted）

**位置：** ADR-0025 D4a 匹配步骤 4 + informative 段。

**现象：**

1. 多候选成功时消歧为「模板字符串**字符数**降序；并列取 `pages[]` 声明序」。
2. 段数相同的 `/orders/new`（11 字符）与 `/orders/{id}`（12 字符），对 path=`/orders/new` 时**参数模板胜出**（`id=new`），字面量路由成死配置。
3. 同节 informative 写「同时注册二者时依赖最长优先得到确定性结果」，暗示该对是合理生产形态，与算法实际相反。

**冲突双方：**

- 正文规范性算法（字符长度）。
- informative 示例与 Admin 路由常识（字面量应优先于参数段）。

**影响：**

- 算法已「唯一确定」，但确定结果业务错误；实现若「按字面」则一致地错，若「按常识修正」则互操作分裂。
- conformance 无法同时服务两种解释。

**建议裁决（维护者 Q1）：**

- **A（推荐）：** 字面量段数降序 → 字符长度降序 → 声明序。
- **B：** 保持纯字符长度，并 M1 静态拒绝任何可重叠模板对。

**建议改法（若选 A，可粘贴）：**

> 多候选同时成功时，按以下键排序取唯一胜者：  
> (1) **字面量段数量**降序（`{name}` 段不计为字面量）；  
> (2) 仍并列则 **模板字符串长度**（字符数）降序；  
> (3) 仍并列则 `pages[]` **声明序**更靠前者。  
> 因此 `/orders/new` 与 `/orders/{id}` 同时匹配 `/orders/new` 时，字面量段更多的 `/orders/new` 胜出。  
> conformance 必须覆盖该对及「两纯参数模板仅靠声明序」向量。

### V314（🔴）navigate 命中注册表仅「宜」注入 `$context.route` — 开放（阻断 accepted）

**位置：** ADR-0025 D4 navigate 接缝；对照 ADR-0021 / `07` §3.2。

**现象：** `type:navigate` 的 url **不强制**命中注册表（v2.x 兼容，合理）；但 path **能**按 D4a 命中时，仅写宿主**宜**按注册表打开并注入 `$context.route`；conformance 只覆盖正例、不把未注入列错。

**影响：** 深链接/home 已强制 D4a→`$context.route`；列表→详情若仍走 `navigate`+`navigateMapping`，一半实现注入 `params`、一半只改 location，则依赖 `$context.route.params.*` 的记录页在「任意前端」下不可互操作。

**建议裁决（维护者 Q2）：**

- **A（推荐）：** 命中则 **必须** 按 D4a 注入；未命中仍允许 navigate。
- **B：** 维持「宜」+ 仅正例 fixture。

**建议改法（若选 A）：**

> 当 navigate 解析后的应用内 path（去 query）能按 D4a 命中恰好一个注册 `route` 时，宿主**必须**以该命中填充 `$context.route`（`path`/`params`/`query`），与深链接同源。  
> 未命中注册表时保持 v2.x：允许导航，`$context.route` 按 0021 最小形状填充（`params` 可为空对象），**不**因此拒绝 navigate。

### V315（🔴）路径三分法与 07 / 0021 / 08 历史「baseURL」口径冲突 — 开放（阻断 accepted）

**位置：** ADR-0025 D1b；对照 `07` navigate「baseURL 下的单斜杠相对地址」、0021 D2「path = baseURL 之后的应用路径」、`08` §6.1 API `baseURL`。

**现象：** 0025 正确钉死三分法（API `baseURL` / 应用路由根 / `https:` logo），但交付清单**未**要求回写 07/0021/08；D1b 补充句仍用 0021 的「baseURL 之后的应用路径」复述，在 API 与前端不同源时字面矛盾。

**影响：** 实现者会把 `pages[].route` 误拼到 API host，或把 `schemaUrl` 当前端路由；发布后「以谁为准」双源。

**建议改法：**

> 规范性术语：`RendererConfig.baseURL` **仅**用于 HTTP（DataRef / schemaUrl / 相对 logo / Action request）。`pages[].route`、`navigation` link.`url`、`type:navigate` 的 url、`$context.route.path` 一律相对**应用路由根**，禁止经 API `baseURL` 拼 host。  
> 接受本 ADR 时必须同步修订 `07` navigate 一行与 0021 D2 的「baseURL 之后」措辞。

### V316（🟡）D4a path 段解码算法未钉死 — 开放（阻断 accepted）

**位置：** ADR-0025 D4a 匹配步骤 3。

**现象：** 只写「解码后的 path 段字符串」，未钉死：按段 percent-decode 算法、非法 `%`、`+` 是否变空格、NFC、解码失败是候选失败还是整次失败。

**影响：** 深链接与 0026 高亮同一权威算法；编码边缘例无法逐字段对齐 fixture。

**建议改法：**

> 分段后对每一段独立做 UTF-8 percent-decoding（RFC 3986）：仅解码 `%HH`；`+` 保持字面 `+`；非法 `%` 序列 → 该候选失败；不对段做 NFC/NFKC。`params[name]` 为解码后的 Unicode 字符串。

### V317（🟡）`TABLE_SORT_FIELD_UNKNOWN` 触发集与登记 — 开放（阻断 accepted）

**位置：** ADR-0027 D4；交付清单。

**现象：** 触发面写「非法/未知 sortKey（例如被篡改的状态）」；表格 `sort` 在 0011 中是 Renderer 内部状态；与 L2 已拒绝的非法 `defaultSort` 如何分工、是否禁止发请求，均未向量化。交付未显式登记该稳定错误码权威位置。

**建议裁决（维护者 Q3）：**

- **A（推荐）：** 保留码，收紧触发集并补 fixture。
- **B：** 删除稳定码，只靠 L2。

**建议改法（若选 A）：**

> 仅当当前表格状态 `sort` 非 null，且其 `sortKey` **不是**任一 `sortable: true` 列的 `sortField ?? field` 时，构造请求前必须失败，码 `TABLE_SORT_FIELD_UNKNOWN`，**不得**发请求、不得静默改写为 null 后继续。  
> 合法来源仅：用户点击可排序列、或实例创建时的 `defaultSort`（已由 L2 保证可命中）。

### V319（🟢）匹配输入 `P` 前置条件未闭合 — 开放

**位置：** 0025 D4a 步骤 1；D3a 落地 path。

**现象：** 明确不去尾 `/`；未规定应用根是 `""` 还是 `"/"`、basename 剥离后的可观测约定、home 落地后 `$context.route.path` 是否必须等于注册 `route` 字面量。

> 匹配输入 `P` 必须：以 `/` 开头；不含 query/fragment；已剥离宿主部署 basename；不得为空字符串（应用根用 `/`）。

## 必须补测的 conformance 向量（接受后落地，本审计跟踪意图）

完整向量表见同轮 checklist「Conformance 意图清单」。关键强制项：

- D4a：`/orders/new` vs `/orders/{id}`（依赖 V313 裁决）
- navigate 命中注册表必须注入 params（依赖 V314）
