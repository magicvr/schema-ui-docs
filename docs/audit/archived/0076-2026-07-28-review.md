## 问题详情

### V362（🟢 P2）MCP lock 父包版本残留 2.5.3；release 门禁漏检 — 已关闭

**位置：** `mcp/package-lock.json` → `packages[".."]`；`scripts/mcp-release-check.js`。

**初审行为：**

- `mcp/package.json` / lock root / 根 `package.json` 均为 **2.6.0**。
- `mcp/package-lock.json` 的 `packages[".."].version` 仍为 **2.5.3**（`file:..` 工作区快照）。
- 正式 tag `v2.6.0` 已带该漂移；`v2.5.2` / `v2.5.3` 的 parent 与 root 曾一致。
- `npm ls --prefix mcp` 运行时解析为 `schema-ui-protocol-workspace@2.6.0`（正确）。
- `mcp-release-check` 仅断言 `lock.version` 与 `packages[''].version`，**不**检查 `packages['..']`。

**冲突证据：**

```text
node -e "… mcpLock.packages['..'].version …"
# → "2.5.3"  vs  package.json "2.6.0"
git show v2.6.0:mcp/package-lock.json  # parent 同样为 2.5.3
```

**影响：** 不阻断构建、conformance、正式 tar/GHCR；lock 元数据与「lockfile 统一 2.6.0」口径不一致，扫描器/后续 `npm install` 易误读父包版本；门禁无法 fail-closed 防复发。

**修复（步骤 3）：**

1. `npm install --prefix mcp --package-lock-only` 将 `packages[".."].version` 刷新为 **2.6.0**（仅 1 行版本字段）。
2. `scripts/mcp-release-check.js` 断言 `packages[".."]` 存在，且 `name` / `version` 与根 `package.json` 一致。

**关闭证据：** `npm run release:check:mcp` 绿；lock parent = `2.6.0`。

**查重：** 非 0074/V351（DOC_MAP 测试）或 0072 lock 根版本类问题；属 2.6.0 升版时 parent 快照未重生成。
