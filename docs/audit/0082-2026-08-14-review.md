## 问题详情（V394–V398）

### V394（P2）`03` OptionsSource.params 行未同步路由绑定语法

`03` 的 select OptionsSource 表格 `params` 行仍写「值仅允许 string/finite number/boolean/null，
或完整单个 `$deps.<path>` 整值替换」，未提 since 2.9 的路由绑定。`02`/`04`/`08` 均已同步，
只读 `03` 的读者会漏掉新语法。

**修复：** `03` OptionsSource.params 行补「或完整单个 `$context.route.query.*` /
`$context.route.params.*` 整值替换（since 2.9 / ADR-0039，capability `data.route-binding`）」。

### V395（P2）`02` §11.3 L3a 报错语义与 `06` L2 行滞后

- `02` §11.3 顶部 L3a 报错语义注仍写「仅 recordSource 绑定」，未提 params 值替换放行；
- `06` L3a 行新增的「L2 另对 params 路由绑定与字段 readOnly 执行版本/capability 双重门控」
  放在 L3a 行内位置不当，应移入 L2 行。

**修复：** `02` 注更新为「仅 recordSource 绑定或 params 值替换（ADR-0039）」；`06` L2 行补
「v2.9 门控」句，L3a 行还原为纯 L3a 职责。

### V396（P3）`08` 新增小节编号层级不一致

新增「字段只读 readOnly」小节用 `#### 2.5.1`，而同层「记录加载」用 `### 2.5.1`（h3），
编号与层级双冲突。

**修复：** 改为 `### 2.5.2 字段只读 readOnly（since 2.9 / ADR-0040）`。

### V397（P3，备注）新建场景 modal create 的 readOnly 值源依赖 Host

`admin-list-route-filter-lifecycle` 示例中 modal 内 create 表单的 `readOnly` dictKey 字段在
协议层没有路由注入通道（modal 内 route 注入非互操作门禁，ADR-0021 V280）。示例已在「关键点」
注明值源责任归属页面生产方/Host。**不阻断发布**；若下游确需 modal 内路由初值，属后续 ADR
候选（与 create 默认值缺口同源）。

### V398（P3，备注）路由绑定键仅支持单段标识符

`$context.route.query.*` 绑定点路径只允许 `[A-Za-z_][A-Za-z0-9_]*` 单段（与 recordSource
绑定一致），URL query 中常见的连字符键（如 `?dict-key=x`）无法绑定。**不阻断发布**：与既有
recordSource 绑定同约束，保持最小面；如未来需要，另行 ADR 增宽。
